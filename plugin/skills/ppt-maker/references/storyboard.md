# storyboard — 장면 흐름 설계

BRIEF가 확정되면 HTML 전에 장면 표를 만든다. 형식은 `assets/storyboard.md`. 저장 위치는 `topics/<slug>/_work/storyboard.md`.

## 1. 장면 표 열

| 열 | 뜻 |
|---|---|
| # | 순번(1부터). HTML의 `data-slide` |
| 장면 ID | 기획 ID(S01, G01, LAB03 …). 순번이 바뀌어도 그대로 → `data-scene-id` |
| 타입 | `slide-types` 11종 중 하나 |
| 제목 | `.scene-title`에 들어갈 **용어 하나 또는 짧은 명사구**(12자 안팎). 예: `토큰 (Token)`. 문장·비유를 붙이지 않는다(비유는 한 줄 요지로) |
| 한 줄 요지 | 이 장면이 청중에게 남길 한 문장. 화면에서는 제목 아래 `.thesis`에 들어간다. 제목과 요지를 합치지 않는다 |
| 시각 요소 | 이미지·도식·숫자 카드 등(edu는 장면마다 1개 이상) |
| 노트 요점 | 발표자가 말할 핵심 2~3개 |
| 출처 | 수치·인용이 있으면 |

## 2. 장수 배분

- 발표 시간 기준: 장면당 1~2분(설명형), 실습 안내 장면은 실습 시간과 별개로 센다
- 도입 10~15% / 본론 70~80% / 마무리 10%
- **S01 표지 다음은 목차 장면**(장수 6장 이상이면 필수, 타입 `title-bullets` 또는 `steps`). 구간 이름과 번호(1/N…)를 여기서 정하고, 뒤 장면의 구간 표시가 이 번호를 따른다. edu는 목차에 구간별 학습 목표를 함께 둔다. 이유: 청중이 전체 흐름과 "지금 어디쯤인지"를 잡을 기준이 목차뿐이다
- **구간 표지는 장수와 관계없이 둔다**(`section_dividers: true`가 기본): 목차의 구간마다 `title` 타입 표지 한 장(`.eyebrow`에 `n/N`, 제목에 구간명). 그리고 내용 장면의 `.eyebrow`에도 `구간명 · n/N`을 쓴다. 이유: 8장짜리 덱에서도 표지가 없으면 청중이 어느 구간인지 구분하기 어렵다는 사용자 피드백(P7 iteration-1). 사용자가 intake에서 표지 없이 가기를 고른 경우만 `section_dividers: false`
- **요청 장수는 내용 장수다**: "8장 만들어줘"는 표지(S01)와 구간 표지를 뺀 내용 장면 8장이다. S02 목차·마무리 장면은 내용 장면에 넣는다(마무리는 `title`이 아닌 타입으로 — `title`은 표지·구간 표지 전용이라 장수 셈에서 빠진다). BRIEF `slide_count`에는 내용 장수를 적고, 스토리보드 머리에 "내용 N장 + 표지 1 + 구간 표지 K = 전체 M장"을 적는다
- edu는 역방향 설계: 학습 목표 → 확인 방법 → 활동 → 설명 순으로 먼저 정하고 장면을 채운다(`edu-designer`)
- reading은 책의 흐름(부·장) 또는 발제 질문 3~5개를 뼈대로. **발제 앞에 "책 소개" 구간을 둔다**: 어떤 책인가(책 표지 자리·출간 정보) → 저자(저자 사진 자리·배경) → 핵심 개념(책의 용어를 정의 한 줄씩). 이유: 청중이 책과 저자를 먼저 잡아야 발제 질문이 붙는다(P7 iteration-1 사용자 피드백 — 이 구성이 기준선이 더 좋았던 점). 사용자가 흐름을 따로 주면 그것을 따른다
- **이미지 자리표시를 계획한다**: 실물 이미지가 설명을 대신하는 자리(책 표지, 인물 사진, 제품·화면 캡처, 현장 사진)는 스토리보드 시각 요소 열에 `[이미지 자리: 무엇]`으로 적는다. 이미지를 지어내거나 외부에서 불러오지 않고 빈 자리로 빌드한다(build-rules.md 4절). 도식만으로 채운 덱은 시각 경험이 떨어진다는 사용자 피드백(P7 iteration-1)
- 내용 장수가 BRIEF `slide_count`와 달라지면 BRIEF를 같은 단계에서 고치고 사용자에게 알린다

## 3. 흐름 점검

- 앞 장면이 예고한 것을 뒤 장면이 회수하는가(예고–회수 짝)
- 정의는 처음 나오는 곳 한 곳에만, 뒤에서는 짧은 이름으로 되짚는다
- 구간 표지가 목차의 구간마다 한 장 있는가(`section_dividers: false`면 생략). 모든 내용 장면의 `.eyebrow`가 목차의 구간 번호와 맞는가
- 제목이 전부 명사형인가(문장형 제목은 `.thesis`로 내린다)
- 마지막 장면이 핵심 메시지로 닫히는가

## 4. BLOCK 나누기 (20장 초과)

- 6~10장씩 BLOCK(B1, B2 …)으로 나눈다. 구간 경계와 맞추면 좋다
- 표 아래에 BLOCK 표를 둔다: BLOCK · 장면 범위 · 담당 · 상태
- 진행 상태는 `_work/progress.md`에도 같은 표로 적는다(중단돼도 이어서 할 수 있게)

## 5. 확인받기

장면 표를 사용자에게 보여 주고 "장수·흐름 OK?"를 묻는다. 승인 전에는 문구 단계로 넘어가지 않는다.
