# intake — 질문으로 BRIEF.md 확정하기

주제만 받고 바로 만들면 엉뚱한 초안이 나온다. intake는 "무엇을, 누구에게, 어떤 틀로" 만들지 먼저 합의하는 단계다. **BRIEF.md가 `status: confirmed`가 되기 전에는 HTML을 쓰지 않는다**(게이트 A).

## 1. 순서

1. 기존 topic 확인: `topics/*/BRIEF.md`에 같은 주제가 있으면 새로 만들지 말고 이어서 한다.
2. 라운드 1 → 라운드 2 → 자유 입력(아래).
3. `new_topic.py`로 폴더를 만든다. BRIEF는 `status: draft`로 생긴다.
4. `intake-router`에게 참고자료를 읽혀 BRIEF 본문 초안을 채운다.
5. 7절 "미확정 질문"이 남아 있으면 모아서 한 번에 묻는다.
6. BRIEF 전체를 사용자에게 보여 주고 승인받으면 `status: confirmed`.

사용자가 "그냥 만들어줘", "알아서 해줘", "질문은 한 번만"이라고 해도 질문을 생략하지 않는다(SKILL.md 4절 1항: 사람이 있는지는 말투가 아니라 AskUserQuestion 도구 가용성으로 판정). 대신 질문 수를 줄인다 — 추천값을 첫 선택지(Recommended)로 두고, 필요하면 라운드 1·2를 한 번의 AskUserQuestion(최대 4문항)으로 합친다. 6번의 승인 질문은 어떤 경우에도 둔다. 사람이 있는 세션에서 스킬이 추천값으로 채운 BRIEF를 스스로 `confirmed`로 바꾸는 것은 게이트 A 위반이다. AskUserQuestion 도구 자체가 없는 무인 실행(`claude -p`)만 예외이며, 그 절차는 SKILL.md 4절 1항을 따른다.

## 2. 라운드 1 (AskUserQuestion, 선택형 4문항)

| 질문 | 선택지 예 |
|---|---|
| 자료 유형 | 교육 교안(edu) / 독서모임 리딩자료(reading) / 일반 발표(general) / 기타 |
| 목적 | 개념 이해 / 실습 안내 / 의사결정 설득 / 결과 보고 / 토론 유도 |
| 청중 | 입문자 / 실무자 / 관리자·경영진 / 혼합 |
| 사용 상황 | 구두 발표 / 배포해서 읽기 / 둘 다 |

## 3. 라운드 2 (선택형 4문항 이내, 필요한 것만)

| 질문 | 선택지 예 |
|---|---|
| 장수 | 유형 프리셋 범위에서 2~3개(edu 20~40, reading 10~15, general 8~15). **내용 장수**로 묻는다 — 표지·구간 표지는 따로 붙는다고 질문에 적는다. 사용자가 "20장"처럼 숫자를 이미 말했으면 다시 묻지 않고 내용 장수로 받는다. 셈법을 꼭 물어야 하면 추천값(Recommended)은 **"내용만 N장(표지·구간 표지 별도)"**이다. "표지 포함 총 N장"을 추천으로 두지 않는다(P7-4 라이브 런에서 규칙과 반대 추천이 나옴). 목차 장면은 내용 장수에 들어간다 |
| 톤 | 존댓말 설명체 / 담백한 보고체 / 대화체 |
| 디자인 | `design-inputs/`의 `DESIGN-*.md` 목록(동적으로 나열) / 내장 팔레트로 / getdesign.md로 새로 받기 |
| 구간 표지·발표자 노트 | 둘 다(Recommended) / 노트만 / 둘 다 없음. 구간 표지는 장수와 관계없이 추천한다(storyboard.md 2절). 어느 쪽이든 S02 목차 장면과 내용 장면 `.eyebrow` `구간명 · n/N`은 둔다 |
| 진행 방식 | 1인 진행(청중 반응을 요구하는 문장 금지) / 상호작용 |
| 시간 표기 | 첫 장(시간표)에만 / 전체 / 없음 |
| 용어 스타일 | 전문용어 + 우리말 부제 / 비유 허용 |

한 번에 4문항까지만 묻는다. 항목이 많으면 라운드 2를 둘로 나눈다.

## 4. 자유 입력 (한 메시지로 요청)

- **스토리라인**: 원하는 흐름(구간 순서)이 있는가. 있으면 그대로 BRIEF 3절 뼈대로 쓴다
- **꼭 넣을 내용**: 빠지면 안 되는 개념·사례·장면·자료(없으면 "없음")
- 주제 한 줄, 핵심 메시지(청중이 가져갈 한 문장)
- 참고자료: 파일 경로 / 붙여넣기 / URL
- 반드시 지킬 것·금지할 것
- 발표 시간(분) 또는 읽는 상황
- 사실 경계: 확실한 것 / 추정인 것 / 쓰면 안 되는 것(사내 정보 등)

스토리라인과 꼭 넣을 내용은 생략하지 않는다. 사용자가 "알아서"라고 하면 추천 흐름(구간 3~4개 이름과 순서)을 만들어 BRIEF 승인 질문에 함께 보여 주고 "이 흐름으로 / 고칠 것 있음"을 받는다. 이유: 흐름을 스킬이 임의로 정하면 실제 사용에서 발표자의 의도와 어긋난다(P7 iteration-1 사용자 피드백). 무인 실행에서는 추천 흐름을 `_work/decisions.md`에 `[확인 필요]`로 남긴다.

## 5. BRIEF.md

템플릿은 `assets/BRIEF.md`. front matter:

| 키 | 값 |
|---|---|
| `status` | `draft` → `confirmed` |
| `slug`, `title` | 폴더 이름, 덱 제목 |
| `type` | `edu` / `reading` / `general` |
| `audience`, `purpose`, `setting` | 라운드 1 |
| `duration_min`, `slide_count` | 발표 시간, 목표 **내용** 장수(S01 표지·구간 표지 제외) |
| `section_dividers`, `speaker_notes` | `true`(기본) / `false`. `section_dividers`가 `false`면 각 장 `.eyebrow`만 구간 표시를 맡는다(storyboard.md 2절) |
| `tone`, `operation`, `time_display`, `term_style` | 라운드 2 |
| `design_source` | 디자인 출처(파일 이름 또는 `palette:<이름>`) |
| `rules_preset` | `edu` / `reading` / `general` |
| `deliverables` | `[overview, present, pdf]` (+ `pptx`) |
| `export_approved` | 처음엔 `false`. 사용자 "최종 확인" 뒤에만 `true`(게이트 C, 정의는 SKILL.md 2절 게이트 표) |

본문 7절: 목적·핵심 메시지 / 청중 / 흐름과 장수 배분 / 참고 자료와 사실 경계 / 지킬 것·금지 / 디자인 지시 / 미확정 질문. **7절이 비어야 confirmed로 바꾼다.**

## 6. 유형 프리셋 (`assets/deck-rules.<type>.json`)

| 유형 | 장수 | 규칙 |
|---|---|---|
| edu | 20~40 | 존댓말, 발표자 노트 필수, 장면마다 시각 요소 1개 이상, 출처는 공식 문서·논문만, 선택: 전문용어 + 우리말 부제 |
| reading | 10~15 | 인용 장면은 쪽수 `p.NN` 필수, 발제 질문은 물음표로 |
| general | 8~15 | 최소 규칙(글자 하한·출처) |

특정 조직 전용 규칙(실습 번호 형식, 내부 코드 이름 등)은 프리셋에 넣지 않는다. 그 topic의 `deck-rules.json`에만 추가한다.

## 7. 디자인을 정하지 않았을 때

`new_topic.py`는 `--design`/`--palette`가 없으면 exit 2로 멈추고 목록을 보여 준다. 아무 파일이나 조용히 고르지 않는다. 사용자에게 셋 중 하나를 고르게 한다.

1. `design-inputs/`의 기존 DESIGN 파일
2. getdesign.md에서 참고 사이트 디자인을 받아 `design-inputs/`에 저장
3. 내장 팔레트 9종(`deck-design/references/palettes/`)
